# Biserry v7.1 — Spark-Safe Phase 2

## Added
- My Biserry customer account using Firebase Authentication email/password.
- Saved default delivery details in `customers/{uid}`.
- Signed-in checkout links orders to `customerUid`.
- Buy Again from the customer's latest account-linked orders.
- In-app dispatcher requests for signed-in customers.
- Dispatcher PWA job inbox: Accept, Decline, Picked Up, On the Way, Delivered.
- Dispatcher job progress synchronizes the private order and sanitized public tracking record.
- New `orderTracking` collection keeps guest tracking public without exposing name, phone, email or delivery address.
- Admin dashboard changed to count queries + small operational windows rather than full catalogue/order downloads.
- Firebase Storage imports removed from the shared Firebase service because Cloud Storage for Firebase requires Blaze billing as of 2026. Existing local/external image URLs continue to work.
- Example hardened Firestore rules: `firestore.rules.v71-example`.

## Spark plan design
This release does not require Cloud Functions, Cloud Tasks, Firebase Storage, paid SMS, paid WhatsApp Business messaging or paid AI APIs.

## Important setup
1. In Firebase Authentication, enable **Email/Password** sign-in.
2. Merge/test `firestore.rules.v71-example` in the Firebase Rules playground before publishing.
3. Do NOT deploy the `/functions` folder on Spark. It remains only as a future optional backend scaffold.
4. Existing orders created before v7.1 do not automatically have `orderTracking` documents. New orders do.

## Cost boundary
Features that require Blaze or third-party charges remain optional and must not be activated without owner approval.
