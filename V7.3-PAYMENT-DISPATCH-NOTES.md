# Biserry v7.3 — Bank Transfer, Payment Release & Rider Earnings

## What this release adds

- Bank-transfer-only checkout (Cash/POS removed).
- Delivery region must be selected before full address.
- Fixed delivery fee per region.
- Configurable Biserry commission percentage per region (default 20%).
- Rider earning and Biserry commission calculated and stored with each zone.
- Customer order total includes product subtotal + delivery fee.
- Payment page with bank details, transaction reference and payment receipt upload.
- Admin Payments screen for Approve / Reject.
- Payment approval automatically changes `paymentStatus` to `Paid` and `deliveryReleaseStatus` to `Authorized`.
- Assigned rider sees payment lock/unlock in real time.
- Rider cannot complete/release a delivery while payment is locked.
- Rider workflow: Offered → Accepted → Picked Up → On the Way → Arrived → Delivered & Released.
- Completed rider earning becomes `Earned` and appears in Rider Wallet.
- Admin Rider Settlements ledger and `Mark Paid` action.
- Admin dashboard payment-verification counter.
- Browser alerts for new payment proofs while the Payments screen is open.
- Browser job alerts for riders while the Dispatcher PWA is running.

## Payment receipt storage

Firebase Storage is NOT used because Biserry is remaining on Firebase Spark. Receipt uploads support Cloudinary client-side unsigned uploads.

Cloudinary configuration:
1. Create a Cloudinary account (the Free plan can be used for this phase).
2. Create an **unsigned** image upload preset in Cloudinary Console → Settings → Upload → Upload Presets.
3. Restrict the preset to images and use sensible file-size/format limits.
4. In Biserry Admin → Payments, save:
   - Cloudinary Cloud Name
   - Cloudinary Unsigned Upload Preset
5. Never place a Cloudinary API secret in Biserry browser JavaScript.

If Cloudinary is not configured, a customer can still submit the bank transaction/reference number and use the WhatsApp notification button; image upload remains unavailable until configured.

## WhatsApp notification

This release uses a free one-tap WhatsApp notice after payment proof submission. Fully automatic server-originated WhatsApp messages require the WhatsApp Business Platform/provider and may carry messaging fees, so that is NOT activated.

## Browser/PWA notifications

Admin payment alerts and rider job alerts work through browser notifications while the relevant app/page is running. Reliable background push while the app is fully closed normally requires a trusted push-sending backend; Biserry does not enable Cloud Functions in this Spark-only release.

## Deployment

Upload the v7.3 patch files and replace the COMPLETE Firestore Rules in Firebase with:

`firestore.rules.v73-payment-dispatch`

Do not append the v7.3 rules below older rules.

After deployment:
1. Admin → Delivery Zones: recreate/update each active zone so it contains fee, commission and rider earning fields.
2. Admin → Payments: enter Biserry bank details and admin WhatsApp number.
3. Optional receipt upload: configure Cloudinary Free + unsigned preset and save the Cloudinary fields in Admin → Payments.
4. Place a NEW test order after v7.3 is live. Older orders may not contain the new zone/commission fields.
5. Submit payment proof.
6. Approve it in Admin → Payments.
7. Confirm rider app changes to PAYMENT CONFIRMED / RELEASE AUTHORIZED.
8. Complete delivery and verify rider earning in Admin → Rider Settlements.
